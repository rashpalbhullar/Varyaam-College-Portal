One-time Supabase SQL setup (run once in SQL Editor)

This creates a separate status table. It does not change or overwrite the imported GNDU student or subject records.

create table if not exists public.gndu_exam_student_status (
  school_code text not null,
  exam_session text not null,
  student_id bigint not null,
  student_status text not null check (student_status in ('Regular','Reappear')),
  updated_at timestamptz not null default now(),
  primary key (school_code, exam_session, student_id)
);

alter table public.gndu_exam_student_status enable row level security;
grant select, insert, update, delete on public.gndu_exam_student_status to anon, authenticated;

drop policy if exists "GNDU exam student status access ITCW ALGON" on public.gndu_exam_student_status;
create policy "GNDU exam student status access ITCW ALGON"
on public.gndu_exam_student_status
for all to anon, authenticated
using (school_code = 'ITCW-ALGON' and exam_session = '2026-DEC-ODD')
with check (school_code = 'ITCW-ALGON' and exam_session = '2026-DEC-ODD');
Important: run the SQL above once in Supabase SQL Editor before saving statuses. The status table is separate from imported student/subject data, so original GNDU records remain unchanged.
